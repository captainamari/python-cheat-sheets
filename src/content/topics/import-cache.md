## 核心机制

导入过程查找模块、创建模块对象并执行顶层代码，成功后后续导入通常复用缓存。from module import value 把当时解析到的对象绑定到当前命名空间，之后原模块重新绑定 value，不会自动改变这份绑定。对同一个可变对象的原地修改则可能被两边同时观察到。

## 放到工程里

测试把环境变量改掉再 import 配置模块，可能仍然读到首次加载时缓存的配置。更易测试的方式是把配置读取放进显式函数或构造器，并把结果传给业务对象。模块导入时尽量避免发请求、启动线程或打开连接，让应用入口负责生命周期，测试才能控制何时初始化。

## 容易混淆的边界

随意删除 sys.modules 并重新导入会产生新模块对象，其他地方仍可能持有旧模块或旧类实例。reload 也不是清空所有引用的魔法；从旧模块导入的名称和已创建对象不会自动全部迁移。遇到循环导入时，模块可能只有部分初始化状态，应调整职责边界而非不断移动 import 碰运气。

## 一分钟回答

导入缓存使模块对象与顶层状态复用。测试隔离应针对显式初始化边界，而不是假定重复导入等于重新启动。我会区分模块属性访问和 from 绑定，并减少导入时副作用，必要时用独立进程验证真实启动流程。
