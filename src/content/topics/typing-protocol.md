## 核心机制

名义继承要求显式继承某个基类，结构化类型则关心对象是否提供所需能力。Protocol 可以声明方法及属性，让业务函数依赖较小接口，而不绑定具体实现。正常 Python 运行不会因参数注解自动拒绝不匹配对象，静态工具与运行时执行承担不同职责。

## 放到工程里

例如存储层只需要 get 方法，就可以声明小型协议，让内存实现、数据库适配器和测试替身都满足它。边界读取 JSON 时仍应检查字段、类型、范围与缺失值，然后转换为内部对象。协议帮助减少耦合，输入校验负责把不可信或不完整的数据变成满足业务约束的数据。

## 容易混淆的边界

@runtime_checkable 允许部分 isinstance 检查，但主要检查成员存在，不会完整验证参数和返回类型。一个同名但签名错误的方法仍可能通过这种检查。不要以它为依据省略调用测试，也不要用复杂协议替代清晰的小接口。泛型、可变属性与协变问题需要静态检查器支持和明确设计。

## 一分钟回答

Protocol 表达结构契约，静态检查器发现调用不匹配；运行时边界校验负责实际数据。两者互补。我会用最小协议描述依赖，真实实现和替身都跑契约测试，而不是把 isinstance 通过当作业务正确证明。
