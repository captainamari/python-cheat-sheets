## 核心机制

较早版本默认在定义时求值许多注解，from `__future__` import annotations 可以保存字符串形式；Python 3.14 又引入延迟求值机制。inspect.get_annotations 提供统一入口，但具体返回格式、字符串求值与命名空间仍需明确。跨版本库应针对支持矩阵测试，而不是依赖直接读取某个内部属性的偶然结果。

## 放到工程里

依赖注入、序列化框架和插件发现可能在运行时分析注解，应在受信任代码边界内进行。需要解析前向引用时，要提供正确的全局和局部命名空间，并处理名称尚未定义的情况。读取后还需要区分类型、字符串和其他合法注解值，注解不是强制只能保存 class 的字段。

## 容易混淆的边界

eval_str=False 只能避免相应字符串求值路径，不能被当作对任意不可信对象进行反射的安全沙箱。注解表达式及访问过程都可能执行代码或抛异常。也不要把运行时注解读取等同于参数校验，函数调用仍不会因为有注解就自动检查实际输入。
