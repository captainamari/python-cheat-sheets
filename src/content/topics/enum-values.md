## 核心机制

枚举成员属于枚举类型，按名字访问和按值构造是两条不同入口，例如 Status["READY"] 与 Status("ready")。默认允许两个名称绑定相同值，后者成为别名，普通迭代通常只列出规范成员。`__members__` 则能显示包含别名在内的名称映射，适合检查完整声明。

## 放到工程里

任务状态、错误类别和配置选项适合枚举，让分支和类型提示更清晰。序列化到 JSON 或数据库时，通常显式选择稳定 value，并把不认识的新值当作兼容性问题处理。枚举只表达有限集合，不自动限制状态迁移；从 running 能否到 cancelled 仍需状态机规则和并发控制。

## 容易混淆的边界

把普通 Enum 与字符串直接比较，不应期待它自动等同于 value。IntEnum、StrEnum 等类型有不同的兼容行为，选择时要考虑是否希望它们与普通基础值混用。unique 能检查重复值，但不能发现所有业务上的非法迁移，也不能自动维护外部协议的历史值。

## 一分钟回答

我用枚举命名有限集合，并明确 name 与 value 的外部稳定性。别名是否允许应在声明时决定，未知输入要显式处理。状态集合与状态迁移分开建模，测试包含序列化、别名和不认识的新值。
